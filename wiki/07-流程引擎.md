# 流程引擎

## 一、核心概念

GeniusFlow 的流程引擎分为**设计态**和**运行态**两个层面：

| 概念 | 说明 |
|------|------|
| **ProcessDefinition**（流程定义） | 设计时创建的流程模板，包含节点和连线的画布 JSON |
| **NodeDefinition**（节点定义） | 流程中每个节点的配置（类型、输入输出 Schema、负责人、AI 参数） |
| **ProcessInstance**（流程实例） | 基于某个已发布流程定义创建的一次执行实例 |
| **NodeInstance**（节点实例） | 流程实例中每个节点的执行对象，含实际输入/输出数据 |
| **Task**（任务） | 节点提交后自动生成的审批任务，分配给责任人处理 |

---

## 二、流程定义生命周期

```
draft（草稿）
  ↓ 设计者完成设计，点击发布
published（已发布）
  ↓ 可基于此版本创建流程实例
  ↓ 需要修改时，发布新版本（同名+版本号+1）
archived（已归档）
```

**规则**：
- `published` 状态的流程定义**不可编辑**，只能创建实例
- 修改流程需新建同名的高版本草稿，发布后替代旧版本
- 同一流程名称的每个版本独立存在，历史实例仍关联原版本

---

## 三、节点类型

| 类型 | 说明 |
|------|------|
| `start` | 开始节点，每个流程恰好一个 |
| `end` | 结束节点，流程执行到此标记完成 |
| `task` | 任务节点，由指定负责人填写输出数据 |
| `approval` | 审批节点，提交后生成审批任务等待审批 |
| `gateway` | 网关节点，用于分支/合并（AND/OR/XOR） |

### 节点配置关键字段

```json
{
  "assigneeId": "用户ID或角色标识",
  "dueHours": 48,
  "enableAiInspection": true,
  "knowledgeBaseIds": ["kb-id-1"],
  "acceptanceCriteria": "具体的验收标准文本",
  "qualityStandard": "适用的质量规范名称"
}
```

## 四、流程实例执行流程

```
创建流程实例
  → 系统自动初始化所有节点实例（status: pending）
  → 开始节点自动变为 in_progress
  → 负责人收到 WebSocket 通知

负责人执行节点
  → 调用 POST /node-instances/:id/save（保存草稿，不触发流转）
  → 节点状态：in_progress
  → 调用 POST /node-instances/:id/submit（提交）
  → 节点状态：submitted

提交后自动触发
  1. 创建 Task 记录（审批任务）
  2. 审批负责人收到通知
  3. Bull Queue 添加 AI 巡检任务（如节点配置了 enableAiInspection）
  4. AI Inspector 完成后写入 AiReport，推送通知

审批处理
  → 通过（POST /tasks/:id/approve）
      节点状态：approved
      触发下游节点变为 in_progress
  → 拒绝（POST /tasks/:id/reject）
      节点状态：rejected
      通知执行人重新处理

流程完成
  → 所有节点 approved → ProcessInstance.status = completed
```

---

## 五、节点实例状态机

```
waiting
  ↓ 分配给执行人，正式开始
in_progress
  ↓ 执行人提交
submitted
  ↓ 审批通过         ↓ 审批拒绝
approved            rejected
                      ↓ 重新执行
                    in_progress（重置）
```

## 六、Gantt 图与进度管理

- 每个节点实例有 `plannedStartDate / plannedEndDate`（计划时间）
- 执行人可通过 `POST /node-instances/:id/progress` 更新完成进度（0-100）
- `GET /process-instances/:id/gantt` 返回 Gantt 图所需的时间轴数据
- 支持设定**基线**（baseline）：保存某时刻的计划数据，用于偏差对比

---

## 七、审计与历史记录

- 每次节点状态变更，系统自动创建 `NodeInstanceHistory` 记录
- 可追溯完整的执行历史：谁在什么时间执行了什么操作，数据是什么
- 所有关键 API 操作还会写入 `AuditLog` 表（含操作人、IP、资源、变更详情）

---

## 八、异步任务队列

后端通过 **Bull（Redis 队列）** 处理耗时操作，避免 API 响应超时：

| 队列名 | 触发时机 | 任务内容 |
|--------|---------|---------|
| `ai-inspector` | 节点提交 | 调用 `/ai/inspect`，写入 AiReport |
| `document-parse` | 文档上传 | 调用 `/ai/parse-path` 解析文本，再调用 `/ai/embed` 向量化 |

队列配置（`ai-inspector`）：
- 最大重试：2 次
- 退避策略：指数退避，初始 2 秒
- 超时：15 秒

## 九、定时任务

`SchedulerService` 使用 `@nestjs/schedule` 注册 Cron 任务：

| 任务 | 频率 | 说明 |
|------|------|------|
| 逾期节点扫描 | 每小时 | 扫描所有已过期未完成的节点实例，推送逾期提醒通知 |

## 十、模板市场

模板是预置的流程定义快照，方便团队复用最佳实践：

1. 设计者将流程定义保存为模板（`POST /templates`）
2. 其他用户在模板市场浏览（`GET /templates`）
3. 点击"克隆"（`POST /templates/:id/clone`）：
   - 系统深拷贝流程定义和所有节点定义
   - **重新映射所有节点 ID**（避免 ID 冲突）
   - 更新 `graphJson` 中的节点 ID 引用和连线 source/target
   - 返回新的流程定义 ID，自动跳转到编辑器
