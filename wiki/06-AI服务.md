# AI 服务

AI 服务是一个独立的 **FastAPI** 应用（`ai-service/`），负责所有 LLM 调用、向量嵌入和语义检索。NestJS 后端通过 HTTP 调用 AI 服务，AI 服务本身不主动对外暴露（通过 Nginx `/ai/` 反向代理）。

---

## 一、服务接口总览

| 路径 | 方法 | 说明 |
|------|------|------|
| `/ai/health` | GET | 健康检查 |
| `/ai/inspect` | POST | 质量巡检（Inspector Agent） |
| `/ai/assist` | POST | 审批建议（Assistant Agent） |
| `/ai/embed` | POST | 文档向量化并存储到数据库 |
| `/ai/search` | POST | 语义检索（向量相似度查询） |
| `/ai/parse-path` | POST | 本地文件路径解析为文本 |

---

## 二、Inspector（质量督导员）

### 功能

在节点提交后，自动对节点输出内容进行质量巡检：
- 对照节点的**验收标准**和**质量规范**
- 可关联**知识库**，检索相关规范文档作为参考
- 输出质量分（0-100）、发现的问题列表、改进建议

### 请求格式

```json
POST /ai/inspect
{
  "nodeInstanceId": "clxxx",
  "nodeName": "需求分析节点",
  "inputData": { "requirements": "..." },
  "outputData": { "analysisReport": "...", "riskList": [] },
  "acceptanceCriteria": "需求覆盖率≥95%，无遗漏的核心功能点",
  "qualityStandard": "符合GB/T 8567-2006软件文档标准",
  "knowledgeBaseIds": ["kb-id-1", "kb-id-2"]
}
```

### 响应格式

```json
{
  "score": 85,
  "summary": "整体质量良好，需求文档结构完整",
  "issues": [
    {
      "severity": "medium",
      "description": "非功能性需求章节描述不够详细",
      "suggestion": "补充性能指标和安全要求"
    }
  ],
  "references": [
    {
      "documentName": "需求规格说明书编写规范",
      "excerpt": "非功能性需求应包含：性能、安全、可靠性..."
    }
  ],
  "recommendation": "建议补充完善后再次提交"
}
```

### 执行链路

```
节点提交（POST /node-instances/:id/submit）
  → NestJS 创建 AiAgentLog 记录
  → Bull Queue 添加 ai-inspector 任务
  → Queue Consumer 调用 POST /ai/inspect
  → Inspector Agent 执行：
      1. 语义检索知识库（若配置了 knowledgeBaseIds）
      2. 构建包含规范参考的提示词
      3. 调用 LLM 生成质量报告
  → 结果写入 AiReport 表
  → WebSocket 推送通知给相关用户
```

## 三、Assistant（审批助理）

### 功能

在审批任务创建后，为管理者提供 AI 辅助决策：
- 分析节点输出数据和 AI 巡检报告
- 评估风险点
- 给出**通过/拒绝**建议 + 置信度 + 理由

### 请求格式

```json
POST /ai/assist
{
  "taskId": "task-xxx",
  "nodeInstanceId": "clxxx",
  "nodeName": "需求分析节点",
  "outputData": { "analysisReport": "..." },
  "inspectionReport": {
    "score": 85,
    "issues": [...],
    "summary": "..."
  },
  "processContext": "这是一个软件研发项目的需求分析阶段"
}
```

### 响应格式

```json
{
  "recommendation": "approve",
  "confidence": 0.82,
  "reasoning": "质量分 85 分，满足验收标准，核心需求覆盖完整，发现的问题属于建议项，不影响后续开发",
  "risks": [
    {
      "level": "low",
      "description": "非功能需求可在后续迭代中完善"
    }
  ],
  "suggestedComment": "质量整体达标，建议通过。请在下一阶段补充性能测试指标。"
}
```

## 四、知识库向量化

### 文档向量化

将文档文本分块并生成向量嵌入，存储到 PostgreSQL（pgvector）：

```json
POST /ai/embed
{
  "documentId": "doc-xxx",
  "chunks": [
    { "index": 0, "content": "第一章 总则..." },
    { "index": 1, "content": "1.1 目的..." }
  ]
}
```

- 嵌入模型：`text-embedding-3-small`（OpenAI，1536 维）
- 存储表：`DocumentChunk.embedding` 列（`vector(1536)` 类型）

### 语义检索

```json
POST /ai/search
{
  "query": "非功能性需求编写规范",
  "knowledgeBaseIds": ["kb-id-1"],
  "topK": 5,
  "threshold": 0.7
}
```

响应：返回最相关的 K 个文档片段及其相似度分数。使用 pgvector 的 cosine 距离进行相似度计算。

### 文件解析

```json
POST /ai/parse-path
{
  "filePath": "/app/uploads/doc.pdf",
  "fileType": "pdf"
}
```

支持格式：`txt`、`pdf`、`docx`。由 `DocumentParser` 服务处理，返回提取的纯文本。

## 五、AI 助理与 Function Calling

AI 助理模式（`/skill-assistant`）由 **NestJS `ai-assistant` 模块**对接，通过 SSE 流式接口提供对话能力。AI 服务为其提供知识库检索支撑。

### Function Calling 支持

当 Agent 技能配置了类型为 `retrieval`（知识库检索）、`api_call` 或 `code_execution` 的技能时，NestJS 调用对应的 LLM（OpenAI / Anthropic Claude）并传递工具定义（`tools` 参数）。模型决策调用工具后：

1. NestJS 收到 `tool_use` / `tool_calls` 响应
2. 向前端推送 `{"type": "tool_call", "name": "工具名"}` SSE 事件
3. NestJS 执行工具逻辑（如调用 `/ai/search` 进行知识库检索）
4. 将工具结果传回 LLM 继续生成回答
5. 推送最终文本内容给前端

### Agent 技能类型

| 类型 | 说明 |
|------|------|
| `retrieval` | 向量检索知识库（调用 AI 服务 `/ai/search`） |
| `api_call` | 调用外部 HTTP API（需配置 URL + 方法） |
| `code_execution` | 执行 Python 代码片段 |

Agent 技能在 **AI 配置 → Agent 技能** Tab 中管理，绑定到角色后可在对话中自动激活。

## 六、模型 Fallback 链

当 AI 服务调用主模型失败（超时、限流、API 错误）时，自动按优先级切换备用模型。

### 配置方式

通过管理后台 **AI 设置 → Fallback 链** 进行配置：
1. 选择模型类型（Chat / Embedding）
2. 添加多个模型，设置优先顺序
3. 可按需启用/禁用单个条目

### Fallback 逻辑

```
调用 chat 模型
  → order=1 的模型（主模型）
      ✓ 成功 → 返回结果
      ✗ 失败 → 尝试 order=2 的模型（第一备用）
                  ✓ 成功 → 返回结果
                  ✗ 失败 → 尝试 order=3 的模型
                              ... 全部失败 → 抛出错误
```

### 排序规则

Fallback 链重排序使用两阶段更新，避免 `(modelType, order)` 唯一约束冲突：
1. 阶段一：将所有条目 order 偏移到 100,000+
2. 阶段二：写入最终 order 值（0, 1, 2...）

## 七、环境配置

```env
# ai-service/.env

# OpenAI（必填）
OPENAI_API_KEY=sk-xxxxx
OPENAI_MODEL=gpt-4o-mini           # 默认对话模型
EMBEDDING_MODEL=text-embedding-3-small  # 嵌入模型

# 数据库（向量检索使用）
DATABASE_URL=postgresql://geniusflow:geniusflow123@postgres:5432/geniusflow

# 请求超时（秒）
REQUEST_TIMEOUT=30
```
