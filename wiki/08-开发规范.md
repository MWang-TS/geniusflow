# 开发规范

## 一、代码组织规范

### 后端（NestJS）

- 每个业务领域对应一个 **Module**，放在 `src/<domain>/` 目录下
- 文件命名：`<domain>.controller.ts`、`<domain>.service.ts`、`<domain>.module.ts`
- DTO 放在 `<domain>/dto/` 目录，使用 `class-validator` 装饰器进行验证
- 数据库访问**只在 Service 层**进行，Controller 仅负责路由和参数解析
- 权限控制使用 `@Roles(...)` 装饰器配合 `RolesGuard`，不在 Service 中做权限判断

### 前端（React）

- 页面组件放在 `pages/`，公共组件放在 `components/`
- API 调用全部封装在 `api/` 目录，页面不直接使用 `axios`
- 状态管理：服务端数据用 TanStack Query，客户端全局状态用 Zustand
- 类型定义：优先在 `api/` 文件中定义接口类型，`types/` 存放公共类型

### AI 服务（FastAPI）

- 每个 API 路由放在 `app/api/` 目录的独立文件中
- 配置统一通过 `pydantic-settings` 管理，不硬编码敏感信息
- LLM 调用使用 `async/await`，设置合理的超时时间

## 二、命名规范

| 场景 | 规范 | 示例 |
|------|------|------|
| 数据库表名 | PascalCase（Prisma 模型名） | `ProcessDefinition` |
| 数据库列名 | camelCase | `createdAt`, `isActive` |
| API 路径 | kebab-case | `/process-definitions` |
| TypeScript 类 | PascalCase | `ProcessDefinitionsService` |
| TypeScript 变量/函数 | camelCase | `findAll`, `processId` |
| React 组件 | PascalCase | `FallbackTab` |
| CSS 类名 | 使用 Ant Design 内置样式，避免自定义 |  |
| 环境变量 | UPPER_SNAKE_CASE | `DATABASE_URL` |

## 三、API 设计规范

- 使用 RESTful 风格，资源名用复数名词
- 统一响应格式通过 `TransformInterceptor` 实现（`{ data, message, statusCode }`）
- 错误统一由 `AllExceptionsFilter` 处理并格式化
- 列表接口支持 `page` + `pageSize` 分页参数（默认 `page=1, pageSize=20`）
- **敏感字段脱敏**：接口返回数据时必须过滤敏感字段（如 `apiKey`），用 `hasApiKey: boolean` 替代

---

## 四、安全规范

### 认证与授权

- 所有受保护路由必须添加 `@UseGuards(JwtAuthGuard, RolesGuard)`
- 角色权限用 `@Roles(...)` 装饰器声明，遵循最小权限原则
- JWT 密钥在生产环境必须使用强随机字符串（≥32 字符），不可使用默认值

### 数据安全

- 密码使用 `bcrypt` 哈希存储，禁止明文
- API Key 等敏感信息存入数据库后，接口响应时**必须脱敏**
- 用户输入通过 `class-validator` 校验，防止注入
- 文件上传限制文件类型和大小，存储路径不可由用户控制

## 五、测试规范

### 单元测试

- 测试文件放在被测文件同级目录，以 `.spec.ts` 结尾
- 使用 Jest + NestJS 测试工具（`Test.createTestingModule`）
- **每个 `describe` 块**必须在 `afterEach` 中关闭 module（防止 Jest open handles）：

```typescript
describe('MyService', () => {
  let service: MyService
  let module: TestingModule  // ← 在 describe 作用域声明

  beforeEach(async () => {
    module = await Test.createTestingModule({ ... }).compile()
    service = module.get<MyService>(MyService)
  })

  afterEach(async () => {
    await module?.close()  // ← 必须关闭，释放资源
  })
})
```

- Mock 外部依赖（HTTP、数据库），不使用真实服务
- 如果代码中有 `setTimeout` / `setInterval`，测试中必须清理（`clearTimeout` 在 `finally` 块）

### 运行测试

```bash
cd api
npm run test             # 运行所有测试（不加 --forceExit 应干净退出）
npm run test -- --watch  # 监听模式
npm run test:cov         # 生成覆盖率报告
```

## 六、提交规范

使用 [Conventional Commits](https://www.conventionalcommits.org/) 格式：

```
<type>(<scope>): <subject>

[optional body]
```

| Type | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `refactor` | 重构（不改变功能） |
| `test` | 测试相关 |
| `docs` | 文档变更 |
| `chore` | 构建/依赖/配置 |
| `perf` | 性能优化 |

**示例**：
```
feat(ai-settings): add model fallback chain CRUD API
fix(templates): remap node IDs when cloning template
test(knowledge-bases): fix Jest open handles in service spec
```

---

## 七、数据库变更规范

- 所有数据库变更必须通过 **Prisma 迁移**（`prisma migrate dev`），禁止直接修改数据库
- 迁移名称使用英文小写加下划线，描述变更内容（如 `add_model_fallback_chain`）
- 迁移文件提交到代码仓库，不可手动修改已应用的迁移
- 生产环境使用 `prisma migrate deploy`（不创建新迁移，只应用待执行的迁移）

---

## 八、环境变量管理

- 所有环境变量在 `.env.example` 中列出（含说明注释），不提交实际 `.env` 文件
- 使用 `@nestjs/config` 的 `ConfigService` 读取，不直接使用 `process.env`
- 生产环境敏感变量（JWT_SECRET、OPENAI_API_KEY 等）通过 Docker Compose `environment` 或 CI/CD 系统的 Secret 管理注入
