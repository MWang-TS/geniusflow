## 三、平台模式

平台支持三种模式，在**登录页**通过 `Segmented` 组件选择，登录后自动跳转对应首页：

| 模式键 | 显示名 | 首页路径 | 侧边栏菜单 |
|---------|------|----------|-----------|
| `workflow` | 流程任务模式 | `/processes` | 流程管理/实例/任务/审批/进度/知识库/模板/通知/系统管理 |
| `assistant` | AI助理模式 | `/skill-assistant` | 技能对话/知识库管理/模板市场/AI角色配置 |
| `api-platform` | AI中台模式 | `/api-platform` | API密钥管理/知识库管理/模板市场/AI角色配置 |

模式状态在 `platform-mode.store.ts` 中用 Zustand `persist` 层持久化到 `localStorage`，页面刷新后保持模式不变。

## 五、状态管理

### 5.1 认证状态（Zustand）

```typescript
// auth.store.ts
interface AuthState {
  user: User | null
  accessToken: string | null
  refreshToken: string | null
  login: (email: string, password: string) => Promise<void>
  logout: () => void
  refreshAccessToken: () => Promise<void>
}
```

Token 持久化：存储在 `localStorage`，Axios 拦截器自动附加 `Authorization` 头。
Token 过期：401 响应时自动调用 `refreshAccessToken()`，失败则跳转 `/login`。

### 5.2 平台模式状态（Zustand）

```typescript
// platform-mode.store.ts
type PlatformMode = 'workflow' | 'assistant' | 'api-platform'

interface PlatformModeState {
  mode: PlatformMode
  setMode: (mode: PlatformMode) => void
}
```

状态通过 `persist` 中间件持久化到 `platform-mode-storage`，刷新页面后保持模式不变。

### 5.3 通知状态（Zustand）

```typescript
// notificationStore.ts
interface NotificationState {
  unreadCount: number
  setUnreadCount: (count: number) => void
  incrementUnread: () => void
}
```

WebSocket 收到 `notification` 事件时自动更新未读计数，顶部导航栏实时显示。

## 六、API 客户端层

所有接口调用统一封装在 `web/src/api/` 目录，通过 Axios 实例发送请求。

```typescript
// 统一 Axios 实例示例（伪代码）
const apiClient = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '/api/v1',
})

// 请求拦截：自动注入 token
apiClient.interceptors.request.use(config => {
  const token = useAuthStore.getState().accessToken
  if (token) config.headers.Authorization = `Bearer ${token}`
  return config
})

// 响应拦截：401 时自动刷新 token
apiClient.interceptors.response.use(
  res => res.data.data,
  async err => {
    if (err.response?.status === 401) { /* 刷新或跳转 login */ }
    return Promise.reject(err)
  }
)
```

## 七、流程编辑器

`ProcessEditorPage` 使用 `@xyflow/react` 实现可视化流程图编辑：

- **节点类型**：start（开始）、end（结束）、task（任务节点）、approval（审批节点）、gateway（网关）
- **状态管理**：节点列表和连线列表维护在本地 state，通过 `onChange` 回调同步到后端
- **保存策略**：自动防抖保存（修改后 2 秒触发），也可手动点击保存
- **节点配置面板**：点击节点打开侧边配置面板，配置节点名称、负责人、输入/输出 Schema、AI 参数（是否启用巡检、关联知识库等）

## 八、AI 配置页面（6 个 Tab）

`/admin/ai-settings` 页面包含 6 个标签页：

| Tab | 组件 | 功能 |
|-----|------|------|
| AI 提供商 | `ProvidersTab.tsx` | CRUD + 连接测试（测试按鈕实时验证 API Key） |
| 对话模型管理 | `ModelsTab.tsx` | CRUD + 设为默认模型（过滤 chat 类型） |
| 知识库模型管理 | `ModelsTab.tsx` | CRUD + 设为默认模型（过滤 embedding 类型） |
| Fallback 链 | `FallbackTab.tsx` | Chat/Embedding 两个子 Tab，拖拽排序，启用/禁用 |
| Agent 技能 | `SkillsTab.tsx` | CRUD，配置技能类型和参数（支持 Function Calling） |
| Agent 角色 | `AgentRolesTab.tsx` | CRUD，配置系统提示词、绑定模型和技能 |

**导入/导出**：页面右上角提供全量导出（下载 JSON）和全量导入（上传 JSON）按鈕，支持一键备份或迁移配置。

## 九、WebSocket 实时通知

```typescript
// useWebSocket.ts 核心逻辑（伪代码）
const socket = io('/ws', {
  auth: { token: accessToken },
  transports: ['websocket'],
})

socket.on('notification', (data) => {
  notificationStore.incrementUnread()
  message.info(data.title)  // Ant Design 消息提示
})
```

后端 WebSocket 网关在 `/ws` 命名空间，连接时验证 JWT，断开时清理 clientUserMap。
