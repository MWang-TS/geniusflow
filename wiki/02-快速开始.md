# 快速开始

## 一、环境要求

| 工具 | 最低版本 | 说明 |
|------|---------|------|
| Docker Desktop | 24+ | 用于容器化部署 |
| Docker Compose | v2 | 随 Docker Desktop 附带 |
| Node.js | 20 LTS | 本地开发前端/后端 |
| Python | 3.11+ | 本地开发 AI 服务 |
| pnpm / npm | — | 包管理器 |

---

## 二、一键 Docker Compose 启动（推荐）

```bash
# 克隆仓库
git clone <repo-url>
cd geniusflow

# 复制环境变量文件
cp api/.env.example api/.env
cp ai-service/.env.example ai-service/.env

# 编辑 api/.env，填写必要配置（见下方环境变量说明）

# 启动全部服务
docker compose up -d

# 查看服务状态
docker compose ps

# 查看日志
docker compose logs -f api
```

启动成功后访问：
- 前端：http://localhost
- API：http://localhost/api/v1
- AI 服务：http://localhost/ai

## 四、环境变量说明

### `api/.env`

```env
# 数据库（Docker 内部使用 postgres 主机名）
DATABASE_URL="postgresql://geniusflow:geniusflow123@postgres:5432/geniusflow"

# Redis
REDIS_URL="redis://redis:6379"

# JWT 密钥（生产环境请替换为强随机字符串）
JWT_SECRET="your-secret-key-change-in-production"
JWT_REFRESH_SECRET="your-refresh-secret-change-in-production"

# AI 服务内部地址
AI_SERVICE_URL="http://ai-service:5000"

# 文件存储目录（可选）
UPLOAD_DIR="/app/uploads"

# 服务端口（容器内固定 4000，外部映射通过 nginx）
PORT=4000
```

### `ai-service/.env`

```env
# OpenAI API Key（必填）

OPENAI_MODEL=gpt-4o-mini

# 数据库（用于向量检索）
DATABASE_URL="postgresql://geniusflow:geniusflow123@postgres:5432/geniusflow"
```

## 五、本地开发模式

本地开发时，数据库和 Redis 仍推荐使用 Docker 运行，前端/后端/AI 服务在本机热重载。

### 5.1 启动基础设施

```bash
# 只启动 postgres 和 redis
docker compose up -d postgres redis
```

### 5.2 启动后端 API

```bash
cd api

# 安装依赖
npm install

# 创建 .env 文件（修改数据库地址为 localhost）
# DATABASE_URL="postgresql://geniusflow:geniusflow123@localhost:5432/geniusflow"
# REDIS_URL="redis://localhost:6379"

# 运行数据库迁移
npx prisma migrate dev

# 注入初始数据（角色、管理员账户）
npx ts-node prisma/seed.ts

# 启动开发服务器（port 4001）
npm run start:dev
```

### 5.3 启动前端

```bash
cd web

# 安装依赖
npm install

# 启动开发服务器（port 3000）
npm run dev
```

### 5.4 启动 AI 服务

```bash
cd ai-service

# 创建虚拟环境
python -m venv .venv
.venv\Scripts\activate      # Windows
# source .venv/bin/activate  # Linux/Mac

# 安装依赖
pip install -r requirements.txt

# 设置环境变量（PowerShell 示例）
$env:OPENAI_API_KEY="sk-xxx"
$env:DATABASE_URL="postgresql://geniusflow:geniusflow123@localhost:5432/geniusflow"

# 启动（port 5000）
uvicorn main:app --reload --port 5000
```

### 5.5 本地开发地址汇总

| 服务 | 地址 |
|------|------|
| 前端 | http://localhost:3000 |
| 后端 API | http://localhost:4001/api/v1 |
| AI 服务 | http://localhost:5000 |
| Swagger（如启用） | http://localhost:4001/api/docs |

> **注意**：本地开发时前端默认通过 Vite 代理访问后端，无需手动配置跨域。

## 六、常用命令

### 数据库操作

```bash
# 查看当前迁移状态
npx prisma migrate status

# 创建新迁移
npx prisma migrate dev --name 迁移描述

# 重置数据库（危险！仅用于开发）
npx prisma migrate reset

# 打开 Prisma Studio（可视化数据库）
npx prisma studio
```

### 后端构建与测试

```bash
cd api
npm run build        # 编译 TypeScript
npm run test         # 运行单元测试
npm run test:e2e     # 运行 e2e 测试
npm run lint         # ESLint 检查
```

### 前端构建

```bash
cd web
npm run build        # 生产构建
npm run preview      # 预览生产构建
npm run lint         # ESLint 检查
```

## 八、常见问题

**Q: 容器启动后前端访问 404**
A: 检查 `docker compose logs nginx`，确认 web 容器已完全构建并启动。

**Q: AI 巡检无结果**
A: 检查 `ai-service/.env` 中的 `OPENAI_API_KEY` 是否正确填写，以及 ai-service 容器是否正常运行。

**Q: 数据库迁移失败**
A: 确认 postgres 容器已启动（`docker compose ps`），再重新运行 `npx prisma migrate dev`。

**Q: 本地开发前端无法连接 API**
A: 检查 `web/vite.config.ts` 中的代理配置，确认后端运行端口与代理目标一致（默认 4001）。
